  • 분석법 적용: 명확하게 추출한 분석법을 우선 적용하고, 없을 때 분석물질의 DB 매칭값으로 보완한다. 명확한 추출값은 DB 값이 다르거나 매칭되지 않아도 덮어쓰거나 NULL로 바꾸지 않는다. 불명확한 원문은 스냅샷과 확인 사유를 보존하되 확정 추출값으로 사용하지 않는다. DB 보완도 대응이 없거나 불명확하면 미확정 업무값은 NULL로 유지한다. 분석법 표시값·시험방법 코드는 같은 방법에 대응해야 하며, 분석법 ID는 실제 적용한 방법과 일치하는 DB 항목에만 연결한다. 다른 방법의 ID를 붙이지 않는다. 직접 추출은 EXTRACTED, DB 보완은 MATCHED로 구분하고 원문·위치·매칭 근거를 보존한다.
  • 목록 매칭은 추출값을 보존한 상태에서 수행. 매칭되지 않은 값을 임의의 목록 ID에 연결하거나 목록 항목을 자동 생성하지 않음.
  • SQL NULL 사용. 문자열 NULL, 안내 문구, 임의 예시값을 저장하지 않음.

원본 위치 및 추출 상태

항목기록 기준
기본 기록 source_locatorA{S}; C{첫 결과 행}:D{마지막 결과 행}. 실제 계산한 행 번호 사용

source_snapshot컬럼별 최초 셀 문자열·해석값·원본 위치 기록. 물질명 C열, 결과 D열, 공통 항목 A열 출처 보존

미추출 필드field_meta.was_extracted=false. 미입력 상태와 추출 후 해석 실패 상태를 구분

  • 추출 상태는 셀의 유의미한 값 유무로 구분. 빈 셀·없는 열을 추출 완료값으로 표시하지 않음.
  • field_meta의 입력 방식·목록 연결 상태 등 공통 구조는 통합 스키마 적용.

구분조건처리
파일 오류인코딩 또는 CSV 파싱 실패추출 중단. 원본을 보존하고 읽기 오류 반환

  • 구간을 확정할 수 있는 필드 오류는 다른 정상 결과의 추출을 막지 않음.
  • validation_issues에 대상 컬럼·오류 코드·수준·안내를 기록. 비수치 표현의 최종 저장 허용 여부는 유형의 input_schema로 검증.

대상변환 기준
파서 반환 구조원본 기록별 records[].basic과 records[].results[]의 1:N 구조 유지. 이하 추출·구분 예시의 record_order는 파서의 원본 기록 순서
원본 기록 순서파서 record_order를 DB 기본 기록의 source_record_order로 매핑. 같은 원본에서 파생된 모든 행에 같은 값 보존
DB 행 순서공통 저장 계층이 파서의 원본 기록 순서 → 그 안의 result_order 순서로 전체 결과를 펼쳐 DB record_order를 1부터 연속 부여
결과 순서DB result_order는 파서의 원본 기록 내 결과 순서를 그대로 보존. 결과별 기본 기록을 생성해도 1로 재설정하지 않음
저장 쌍펼쳐진 결과마다 해당 basic을 복사한 독립 기본 기록 1건과 결과 1건을 1:1로 생성. 서로 다른 결과가 기본 기록을 공유하지 않음
