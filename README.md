## 실행

`index.html`을 브라우저에서 연다. 뷰어는 로컬 파일과 로컬 웹 서버에서 사용할 수 있으며, 외부 서비스 연결이나 패키지 설치 없이 동작한다.

안내·번호표·긴 화면 예시에서 화면 탐색, 확대·이동, 설명 확인과 텍스트·코드 복사 방법을 확인할 수 있다.

## 사용

- 하단 화살표와 키보드 좌우 키는 현재 최상위 목록 안에서 이전·다음 페이지로 이동한다. 다른 목록은 좌측 트리에서 선택한다.
- 좌측 화면 목록은 `<`로 숨기고 왼쪽 가장자리의 `>`로 다시 연다. 우측 설명은 `>`로 숨기고 오른쪽 가장자리의 `<`로 다시 연다.
- 확대·축소와 너비 맞춤은 가운데 목업 영역에 적용한다.
- 화면의 번호표를 누르면 연결된 설명이 강조된다. 설명 패널이 닫혀 있으면 함께 열린다.

## 화면 확대와 이동

- 목업 위에서 트랙패드 핀치를 사용하면 목업만 확대·축소한다. 상단·좌우 메뉴 크기는 유지한다.
- 두 손가락 스크롤 또는 마우스 휠로 화면을 이동한다.
- 목업 위에서 `Space`를 누른 채 마우스나 트랙패드로 드래그하면 화면이 움직인다. 키를 놓으면 텍스트 선택으로 돌아온다.
- `너비 맞춤`은 목업을 가운데 영역의 너비에 맞추고 맨 위로 이동한다. 패널·창 크기가 바뀔 때는 보고 있던 세로 위치를 유지한다.

확대 범위는 10%-200%다. 기본 너비 맞춤은 원본의 100%를 넘겨 확대하지 않는다. 확대할 때는 포인터가 가리키던 화면 위치를 기준으로 배율을 바꾼다. 코드 창과 컴포넌트 선택 중에는 화면 이동 모드를 해제한다.

입력 처리는 [wheel 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event)와 [gesturechange 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/Element/gesturechange_event)를 참고한다. 실제 기기의 트랙패드 동작은 사용하는 브라우저에서 확인한다.

## 긴 페이지 작성

원본 너비는 기본 1280px로 두고, 페이지별 높이를 지정한다. 긴 화면도 너비에 맞춰 상단부터 표시되며, 화면 아래 내용은 스크롤과 드래그로 확인한다.

```js
{
  id: 'long-page',
  title: '긴 화면',
  src: 'pages/long-page.html',
  width: 1280,
  height: 2400
}
```

원본 HTML의 캔버스 높이도 목록에 지정한 높이에 맞춘다. 기본 스타일의 최소 높이는 800px이며, 콘텐츠를 그 높이에서 잘라내지 않는다. 페이지 하단에 고정 배치하는 요소는 페이지 본문을 기준으로 한다.

```css
html, body { height: 2400px; }
body { position: relative; }
```

번호표의 `y`도 원본 페이지 전체 높이를 기준으로 지정한다. HTML/CSS 수정 후 `python3 scripts/build_sources.py`를 실행하면 화면과 복사 코드가 함께 갱신된다. `긴 화면 예시`에서 1280×2400px 구성을 확인할 수 있다.

## 텍스트와 코드 복사

화면 목록, 목업, 설명의 텍스트를 드래그해 선택하고 `⌘C` 또는 `Ctrl+C`로 복사한다.

- 상단 `코드 보기`를 누르면 현재 페이지의 HTML과 CSS를 확인할 수 있다.
- `복사 대상`에서 페이지 전체 또는 등록된 컴포넌트를 선택한다.
- `컴포넌트 선택`을 켜면 화면의 영역을 직접 눌러 해당 코드를 볼 수 있다. `선택 취소`나 `Esc`로 종료한다.
- `코드 복사`로 가져간다. 자동 복사가 허용되지 않으면 선택된 코드에서 `⌘C` 또는 `Ctrl+C`를 사용한다.

페이지 전체는 CSS와 로컬 이미지를 내장한 HTML 문서다. 컴포넌트는 전용 래퍼와 그 안에 한정되는 CSS를 함께 제공한다. 뷰어 메뉴, 번호표, 선택 기능을 위한 스크립트는 복사 코드에 포함하지 않는다. 컴포넌트에는 해당 페이지의 CSS를 래퍼 안으로 제한해 제공하므로, 필요한 규칙을 개발 프로젝트에 맞춰 정리할 수 있다.

## 페이지 추가

1. `pages/`에 새 화면의 HTML 파일을 만든다.
2. `data/manifest.js`에 페이지를 등록하고 위치를 정한다.
3. `data/descriptions.js`에 필요한 번호표와 설명을 등록한다.
4. 아래 명령으로 화면과 복사용 소스를 갱신한다.
5. 브라우저를 새로고침해 페이지와 설명의 연결을 확인한다.

뷰어 폴더에서 실행한다. Python 3.10 이상이 필요하며, 추가 패키지는 사용하지 않는다. 생성 후 뷰어를 사용하는 데 Python은 필요하지 않다.

```sh
python3 scripts/build_sources.py
```

`pages/`의 HTML 또는 CSS를 수정한 뒤에는 이 명령을 다시 실행한다. 생성된 `data/page-sources.js`는 직접 편집하지 않는다. 소스가 생성되지 않은 새 페이지는 화면만 표시되고 코드 복사 버튼은 비활성화된다.

페이지는 `window.MOCKUP_VIEWER_MANIFEST.tree`의 원하는 그룹 안에 다음 형식으로 등록한다. `children`을 가진 항목은 그룹이며, 그룹 안에 다른 그룹을 넣어 깊이를 늘릴 수 있다.

```js
{
  id: 'process-flow',
  title: '전체 순서도',
  src: 'pages/process-flow.html',
  width: 1280,
  height: 800,
  kind: '순서도',
  summary: '파일 업로드부터 결과 확인까지의 흐름입니다.'
}
```

번호표가 필요한 경우 `window.MOCKUP_VIEWER_DESCRIPTIONS`에 같은 페이지 ID로 설명 배열을 추가한다. `x`, `y`는 원본 화면의 왼쪽 위를 기준으로 한 픽셀 좌표다. 번호는 배열 순서에 따라 표시된다.

```js
'process-flow': [
  {
    id: 'start',
    title: '시작 단계',
    body: '해당 단계에 대한 설명을 작성합니다.',
    x: 160,
    y: 120
  }
]
```

설명이 없으면 해당 페이지 ID를 생략하거나 빈 배열로 둔다. 설명 제목은 일반 텍스트로 작성한다. 설명 본문은 일반 텍스트와 정책 항목 링크를 지원한다.

설명 카드에 `label: 'U-01'`을 지정하면 순번 대신 화면 ID를 표시한다. `x`, `y`를 생략하면 목업 위에 번호표를 만들지 않는다. 기본 순서도는 이 방식으로 단계 설명을 표시한다.

화면 파일 이름에는 영문, 숫자, 하이픈, 밑줄을 사용한다. 화면 제목과 설명은 한글로 작성할 수 있다.

오류 화면의 제목은 `오류 화면(단계명)` 형식으로 작성한다. 목록과 브라우저 탭에는 같은 제목을 사용하고, 우측 설명 제목에도 해당 단계명을 표시한다.

페이지 ID와 설명 ID는 순서를 바꿔도 유지한다. 페이지 ID는 전체 목록에서, 설명 ID는 해당 페이지 안에서 고유해야 한다. 화면에서 보이는 페이지 번호는 최상위 목록마다 1부터 시작하며, 해당 목록의 트리 순서로 계산한다. 하위 그룹의 페이지도 같은 최상위 목록에 포함한다. 루트에 직접 등록한 단일 페이지는 독립된 1페이지 범위로 취급한다.

상위 목록은 `화면 기획서`(표지와 업무 화면), `정책`(정책 문서·통합 스키마·기본 순서도·LLM 추출 순서도), `추출 규칙`(인덱스와 개별 규칙), `뷰어 안내`로 구성한다. 각 목록에서 페이지 번호가 1부터 시작하고 하단 이전·다음은 목록 안에서 이동한다. 설명 링크는 고유 페이지 ID로 다른 목록의 문서에도 연결된다.

## 정책 문서와 링크

`정책` 목록의 `정책 문서`는 `docs/rist-policies.md` 한 곳에서 편집한다. 각 정책 제목에 고유 ID를 지정하고, 제목이나 순서가 바뀌어도 ID는 유지한다.

```md
---
version: 1
created_at: 2026-09-16
updated_at: 2026-09-16
---

# 정책 문서

## 로그인 정책 {#login-policy}

- 프로그램 자체 로그인으로 운영합니다.
```

버전·작성일·수정일은 문서 상단의 `version`·`created_at`·`updated_at` 속성에서 관리하며 제목 아래에 표시한다. 날짜는 속성에서 `YYYY-MM-DD`, 화면에서는 `YYYY/MM/DD`로 표기한다.

지원 문법은 `#` 문서 제목, `## 정책 제목 {#고유-id}`, `###` 소제목, 문단, `-` 목록, `**굵게**`다. 정책 ID는 영문 소문자로 시작하는 영문 소문자·숫자·하이픈 조합이며 문서 안에서 고유해야 한다. HTML은 실행되지 않고 텍스트로 표시된다. 표·이미지·코드 블록·중첩 목록 등은 별도로 해석하지 않는다.

수정 후 뷰어 폴더에서 다음 명령을 한 번 실행하고 브라우저를 새로고침한다. `pages/rist-policies.html`과 `data/page-sources.js`는 자동 생성 파일이므로 직접 수정하지 않는다.

```sh
python3 scripts/build_sources.py
```

정책 문서는 너비 1280px로 표시하며 내용이 길어지면 문서 높이에 맞춰 늘어난다.

다른 페이지의 `data/descriptions.js` 본문에는 다음처럼 링크를 작성한다. `#` 뒤는 정책 페이지 ID, `/` 뒤는 정책 항목 ID다.

```js
body: '[로그인 정책](#rist-policies/login-policy)'
```

링크를 클릭하면 정책 페이지로 전환하고 해당 항목으로 이동해 강조한다. 키보드로 링크를 선택하고 Enter를 눌러도 이동한다.

문서 제목 오른쪽 위에 `정책 문서.md`와 다운로드 아이콘을 표시한다. 아이콘을 선택하면 `정책 문서.md`를 내려받는다.

## 스키마 문서와 링크

`정책` 목록의 `통합 스키마`는 `docs/rist-schema.md`에서 관리한다. 문서를 수정한 뒤 `python3 scripts/build_sources.py`를 실행하면 화면과 복사용 코드가 함께 갱신된다. `pages/rist-schema.html`과 `data/page-sources.js`는 생성 파일이다.

스키마는 너비 1280px의 전체 문서로 표시하며, 내용에 따라 세로 길이가 늘어난다. YAML 속성은 본문과 구분하고, 표·제목·목록·굵은 글씨·인라인 코드·문서 내부 바로가기를 표시한다. 테이블 목록의 `상세`를 선택하면 해당 테이블로 이동해 강조한다.

테이블 제목의 ID는 밑줄을 포함한 이름 그대로 유지한다. 문서 안에서는 `[상세](#analysis_record)`, 다른 페이지의 설명에서는 `[분석 기본 기록](#rist-schema/analysis_record)`로 연결한다. 페이지 번호는 목록 순서로 계산하므로 기존 페이지의 고유 ID는 변경하지 않는다.

문서 제목 오른쪽 위에 `통합 스키마.md`와 다운로드 아이콘을 표시한다. 아이콘을 선택하면 `통합 스키마.md`를 내려받는다.

두 문서의 다운로드에는 `docs/`의 MD 원문과 YAML 속성이 그대로 포함된다. 원문을 수정한 뒤 `python3 scripts/build_sources.py`를 실행하면 표시 화면과 다운로드 데이터가 함께 갱신된다. 다운로드 데이터는 뷰어에 포함되므로 로컬 파일 실행과 GitHub Pages의 하위 경로에서도 사용할 수 있다. 뷰어를 게시할 때는 `docs/`와 생성된 `data/page-sources.js`를 함께 포함한다.

## 추출 규칙 문서

`추출 규칙` 목록은 인덱스를 첫 번째로 고정하고 개별 규칙을 유형 코드의 알파벳순·번호순으로 정렬한다. 인덱스와 개별 규칙은 같은 하위 뎁스이며, 하단 페이지 이동도 이 목록 안에서 동작한다.

| 경로 | 내용 |
| --- | --- |
| `docs/extraction-rules/index.md` | 목록 문서. YAML 속성은 직접 관리하고, 본문의 유형별 표는 빌드 시 개별 규칙 문서에서 생성 |
| `docs/extraction-rules/csv/csv-001.md` | CSV-001 규칙 원문 |
| `docs/extraction-rules/pdf/`, `docs/extraction-rules/excel/` | PDF·EXCEL 규칙 문서 |

규칙 문서는 소문자 유형 코드의 MD 파일로 저장한다.

문서를 추가·수정한 뒤 `python3 scripts/build_sources.py`를 실행한다. 인덱스 MD의 유형별 표, 개별 HTML, 정렬된 목록과 화면 데이터가 함께 갱신된다.

각 문서의 `version`, `created_at`, `updated_at`을 버전·작성일·수정일로 표시한다. 다운로드 아이콘 왼쪽에 파일명을 표시하며, 인덱스는 목록 MD, 개별 규칙은 규칙 MD를 제공한다. 문서 다운로드 데이터가 화면 데이터에 포함되므로 로컬 파일과 GitHub Pages의 하위 경로에서도 사용할 수 있다.

인덱스 바로가기는 개별 규칙 페이지로 이동한다. 규칙 MD의 스키마·인덱스 상대 경로 링크는 뷰어의 해당 문서와 항목으로 연결한다. 생성된 `pages/extraction-*.html`과 `data/extraction-rules.js`는 직접 편집하지 않는다.

## 컴포넌트 등록

원본 HTML에서 복사할 영역에 ID, 이름, 기준 폭을 지정한다.

```html
<section
  class="result-card"
  data-component="result-card"
  data-component-title="결과 카드"
  data-component-width="480"
>
  <h2>결과</h2>
  <p>확인할 내용을 배치합니다.</p>
</section>
```

ID는 페이지 안에서 고유한 영문 소문자·숫자·하이픈 조합으로 작성하며, 영문자로 시작한다. `data-component-width`는 선택 항목으로 원본 픽셀 폭이다. 상위 그리드가 정하던 폭을 복사 결과에서도 유지할 때 사용한다.

스타일은 컴포넌트 내부 클래스를 기준으로 작성한다. 다른 영역의 조상 선택자에 의존하는 배치는 복사 영역 안으로 포함한다. 컴포넌트에는 페이지의 고정 캔버스 크기·바깥 여백·overflow 설정을 전달하지 않고, 글꼴·색상·CSS 변수 등 상속 스타일을 보존한다.

일반 선택자, 의사요소와 블록 형태의 `@media`, `@supports`, `@container`, `@layer`를 지원한다. 외부 URL 자산, `@import`, `@font-face`, 키프레임, 루트에 의존하는 복합 선택자 등 지원하지 않는 문법은 생성 시 오류를 표시한다. 로컬 CSS는 `<link rel="stylesheet">`, 이미지는 `img src` 또는 CSS `url()`로 참조한다. `srcset`, 외부 스크립트, 비디오처럼 별도로 처리해야 하는 자산은 현재 생성 범위에 포함하지 않는다.

## 수정과 삭제

화면 배치는 해당 페이지의 HTML에서, 번호표·설명은 설명 데이터에서 수정한다. 페이지 순서와 트리 위치는 화면 목록에서 바꾼다. 페이지를 목록에서 제거하면 탐색 대상에서 빠진다. 관련 화면·설명 파일은 필요한 경우 별도로 정리한다.

공통 메뉴와 조작은 `assets/`에서 관리한다. 페이지에는 해당 목업의 화면만 작성하고, 공통 뷰어 메뉴를 중복해서 넣지 않는다.

## 정적 화면 작성

업로드·입력·저장 등의 전후 상태는 각각의 정적 페이지로 표현한다. 뷰어의 탐색·확대·설명 연결 기능은 실제로 동작하며, 목업 내부의 업무 처리 기능은 구현하지 않는다.

화면 크기와 번호표 좌표는 등록 데이터의 기준 크기에 맞춘다. 화면 확대·축소는 뷰어가 처리하므로 개별 페이지에 별도 확대 기능을 넣지 않는다.

## 검증

뷰어 폴더에서 실행한다.

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
node --test tests/*.test.cjs
```

소스 생성, 코드 복사, 제스처 입력, 확대 위치·스크롤 단위·너비 맞춤 계산을 검증한다. JavaScript 검사는 DOM·클립보드 대역을 사용하는 로직 검사이며, 브라우저의 실제 레이아웃이나 운영체제 클립보드를 검증하지 않는다.
