## 채취일자·분석일자 비교 정책

| 항목 | 기준 |
| --- | --- |
| 화면 ID | rist-phase2-date-comparison |
| 화면 기반 | 2차 2단계·최종 저장 전 검사 화면의 별도 복사본 |
| 비교 단위 | 같은 행의 채취일자와 분석일자 |
| 비교 조건 | 두 날짜가 모두 존재하고 날짜 형식이 유효할 때 |
| 오류 | 채취일자가 분석일자보다 늦음 |
| 문구 | 채취일자가 분석일자보다 늦습니다. 두 날짜를 확인해 주세요. |
| 분석일자 없음 | 선택 항목 미입력으로 표시하고 선후 비교 생략 |

## 검사 시점과 허용 동작

| 시점·행동 | 처리 |
| --- | --- |
| 추출 후 | 전체 행의 날짜 선후 확인 |
| 1·2단계 변경 적용 후 | 변경이 적용된 작업 데이터의 날짜 선후 재검사 |
| 작업 저장 | 날짜 선후 오류가 있어도 허용 |
| 단계 이동 | 날짜 선후 오류가 있어도 허용 |
| 최종 저장 전 | 전체 행 검사. 오류가 있으면 저장 확인창 차단 |

1단계에서 값을 일괄 적용한 경우 대상 전체 행을 같은 기준으로 검사합니다. 이번 화면은 2단계 형식의 독립 예시이며 기존 1단계·최종 검사 페이지를 수정하지 않습니다.

## 오류 예시와 위치 이동

8행의 채취일자는 2026/10/14, 분석일자는 2026/10/13입니다. 최초 5행 표시 상태에서도 8행 오류를 안내합니다.

- 오류 영역에 항목·대상 8행과 사유를 표시합니다.
- 채취일자 확인·분석일자 확인은 각각 해당 열을 펼치고 8행까지 조회하여 셀로 이동합니다.
- 숨긴 열과 아직 조회하지 않은 행도 이동 대상입니다.
- 값을 임의 교환·보정하지 않습니다. 미확정 입력은 먼저 확정하도록 안내하고 유지합니다.
- 변경 적용 후 오류 안내를 갱신하되 자동으로 최종 저장하지 않습니다. 최종 저장은 별도 검사를 거쳐 확인합니다.

## 날짜·시간과 유효성

비교는 날짜 단위입니다. 양쪽에 시간이 있을 때 시간 선후까지 검사할지는 미확정입니다. 시간이 없다는 이유로 00:00을 넣거나 날짜만 있는 값을 특정 시각으로 보정하지 않습니다.

존재하지 않는 날짜·잘못된 형식은 선후 비교와 별도로 검사합니다. 채취일자 누락은 기존 필수값 검사 대상으로 처리합니다. 0·n.d 등 다른 결과값의 공란 판정은 기존 최종 검사 정책을 유지합니다.

## 목업 상태

날짜 오류(8행), 분석일자 없음, 날짜 수정 후 통과 예시를 기획용 컨트롤로 전환합니다. 작업 저장·단계 이동 허용과 최종 확인 차단을 확인할 수 있으며, 실제 API·DB 저장은 수행하지 않습니다.
