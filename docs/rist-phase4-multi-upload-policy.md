## 여러 파일 업로드 정책

### 적용 범위와 관리 단위

첫 화면 중앙의 업로드 영역을 가로 1:1로 나누어 왼쪽은 파일 1개, 오른쪽은 여러 파일의 선택 및 드래그를 제공한다. 단일 파일과 여러 파일의 처리 흐름 및 이력은 분리한다. 오른쪽에서 파일 선택 후 다음 단계로를 선택하면 별도 파일 확인 및 제외 단계 없이 유형 분석을 시작한다.

| 단위 | 관리 기준 |
| --- | --- |
| 업로드 묶음 | 한 번에 접수한 전체 파일과 유형 그룹, 전체 진행 현황 및 이력 진입 |
| 유형 그룹 | 같은 묶음 안에서 동일한 추출 유형으로 분류된 파일의 단계 진행, 전체 검사, 최종 저장 및 미완료 보관 기간 |
| 개별 파일 | 원본, 추출 및 검토 데이터, 오류와 결과 출처 |

서로 다른 업로드 묶음의 파일은 같은 유형이어도 자동으로 합치지 않는다. 같은 유형 그룹 안에서도 파일별 원본과 결과의 구분을 유지한다.

### 업로드 전 선택 상태

단일 파일과 여러 파일의 업로드 전 선택 상태에는 “N개 파일 선택됨”으로 상태와 수량만 표시한다. 파일명 목록, 단일 파일명 및 파일명 툴팁은 표시하지 않는다. 선택한 파일 정보는 유지하며 유형 분석 이후의 파일명 표시는 해당 단계의 기준을 따른다.

### 업로드 한도

| 항목 | 기준 |
| --- | --- |
| 파일 수 | 접수 전 선택한 파일 총수 기준으로 한 번에 최대 20개 |
| 초과 선택 | 20개를 초과하면 접수하지 않고 20개 이하로 다시 선택하도록 안내. 앞의 20개만 임의로 업로드하지 않음 |
| 파일별 용량 | 파일당 20MB 이하 |
| 파일 유형 수 | 등록된 지원 유형에 한해 별도 제한 없음. 미지원 파일은 기존 미지원 처리 기준 적용 |
| 전체 업로드 용량 | 최대 400MB. 개발 검토 의견에 따라 조정 가능. 초과 시 접수 및 진행 차단 |
| 용량 단위 | 파일당 용량과 전체 용량 모두 1MB = 1,024 × 1,024바이트 |

### 유형 분석과 정렬

| 항목 | 정책 |
| --- | --- |
| 분석 | 등록된 추출 규칙으로 파일 유형을 순차 분석하고 전체 파일 수, 분석 완료 수 및 현재 상태 표시 |
| 분석 완료 | 유형별 파일 수와 파일 목록 표시. ‘유형별 검토 시작’을 선택하면 검토 진입 |
| 그룹 순서 | 유형 코드순 |
| 그룹 내부 순서 | 파일명순. 같은 파일명은 업로드 순서로 구분 |
| 선택 순서 | 파일 선택 순서로 그룹 및 검토 순서를 결정하지 않음 |
| 판별 불가 | 사유와 함께 별도 목록 표시. 정상 분류 그룹은 검토 허용 |

### 중복 확인과 검토 제외

단일 파일과 여러 파일 모두 업로드 및 유형 분석 단계에서는 파일명만 비교해 1차 확인한다. 여러 파일은 현재 업로드 묶음 안의 파일과 과거 업로드 이력을 비교하고, 단일 파일은 과거 업로드 이력과 비교한다. 파일 내용의 동일성은 검사하지 않는다. 같은 파일명이 있어도 자동 차단하거나 제외하지 않고 사용자가 검토 포함 여부를 결정한다.

| 항목 | 정책 |
| --- | --- |
| 파일명 일치 | ‘같은 파일명 있음’으로 안내. 내용 동일성을 의미하지 않음 |
| 제외 | 유형 분석 완료 후 파일 목록의 모든 파일 행 우측에 × 버튼 제공. 의미는 ‘검토에서 제외’로 표시 |
| 포함 여부 | 중복 의심 안내를 강조하고 사용자가 검토 포함 여부 결정 |
| 제외 범위 | 현재 묶음의 검토 대상에서 제외. 과거 이력과 기존 저장 데이터는 삭제하지 않음 |
| 대상 수 | 제외 후 전체 및 유형별 검토 대상 파일 수 갱신. 대상이 없는 그룹은 검토 순서에서 제외 |

같은 파일명을 가진 다른 계정의 미완료 작업은 파일명 중복 안내에서 ‘다른 사용자 검토 중 N건’으로만 표시한다. 계정, 업로드 시각, 상세 내용 및 접근 링크는 제공하지 않는다. 건수 안내는 조회, 수정 또는 다운로드 권한을 부여하지 않는다.

### 파일별 검토

공통 1단계, 2단계, 3단계 검토 기능과 입력 규칙을 적용한다. 유형명, 현재 파일명 및 ‘2/5’와 같은 그룹 내 파일 위치를 표시한다. 이전 및 다음 버튼과 파일 목록으로 같은 그룹의 파일을 이동하고 현재 파일과 파일별 검토 상태를 구분한다.

| 단계 | 정책 |
| --- | --- |
| 1단계 | 파일별 기본 정보와 추출 내용을 검토. 파일 이동 시 해당 파일의 입력값 표시. 한 파일의 값을 다른 파일에 자동 복제하지 않음 |
| 2단계 | 파일별 상세 결과 검토. ‘검토 완료 및 저장’은 현재 그룹의 모든 검토 대상 파일 검사 |
| 3단계 | 오류 파일 수와 파일별 오류 표시. 파일, 행, 열로 오류 위치 식별. 오류 파일 우선 이동 지원 |

오류가 없는 파일까지 반복 방문하도록 요구하지 않는다. 검사 통과를 사용자가 파일 내용을 직접 검토했다는 의미로 표시하지 않는다. 날짜와 필수값 등 검사 기준은 공통 정책을 따른다.

파일 이동 후에도 서버에 적용된 파일별 검토 내용은 유지한다. 서버에 적용하지 않은 입력칸의 값은 복원 대상에서 제외한다.

### 그룹 검사와 최종 저장

| 항목 | 정책 |
| --- | --- |
| 검사 대상 | 현재 유형 그룹의 전체 검토 대상 파일과 모든 결과. 화면에 표시된 파일이나 행으로 제한하지 않음 |
| 오류 존재 | 그룹 최종 저장을 완료하지 않고 3단계에서 오류 파일과 항목 안내 |
| 오류 없음 | 그룹 파일 수와 전체 결과 행 수를 표시하고 최종 저장 확인 제공 |
| 저장 단위 | 유형 그룹 단위. 파일별 원본과 결과 출처 유지 |
| 중간 실패 | 일부 파일 저장을 그룹 전체 완료로 표시하지 않음. 실패 범위를 구분하고 다음 그룹으로 자동 진행하지 않음 |
| 다음 그룹 | 현재 그룹 전체 저장 완료를 확인한 뒤 사용자가 다음 그룹 검토를 선택하면 이동 |
| 묶음 완료 | 모든 대상 그룹의 최종 저장 성공 후 완료 |

그룹 최종 저장 성공과 NAS 전송 성공은 별도로 관리한다. 최종 저장 완료 그룹은 NAS 전송 대기 또는 실패 상태여도 미완료 보관 만료 대상으로 되돌리지 않는다.

### 권한

미완료 그룹은 업로드 계정만 조회하고 수정한다. 완료 데이터는 기존 완료 이력 조회 권한을 따른다. 완료 파일의 조회 권한으로 같은 묶음의 다른 계정 미완료 파일 정보를 노출하지 않는다. 직접 주소와 API에도 같은 기준을 적용한다.

보관 기간, 재개 및 원본 다운로드는 [그룹 저장 및 원본 다운로드 정책](#rist-phase4-group-storage-policy)을 따른다.

그룹 전체 최종 저장 성공 시 [그룹 저장 완료](#rist-phase4-group-saved)에서 유형, 파일 수와 결과 행 수를 확인한다. 남은 그룹이 있으면 같은 완료 화면 아래에 다음 그룹 검토 여부와 다음 유형 및 파일 수를 표시하며, 사용자가 다음 그룹 검토를 선택하면 해당 그룹의 1단계로 이동한다. 나중에 검토를 선택하면 해당 업로드 묶음 상세로 이동한다. 단순 보류는 미완료 그룹의 보관 기간을 갱신하지 않으며 기존 권한 기준을 유지한다. 남은 그룹이 없으면 다음 그룹 질문을 표시하지 않고 완료 확인으로 모든 그룹 완료에 연결한다.

추출 실패 및 지원하지 않는 파일은 묶음 상세에 처음부터 그룹 없는 파일로 표시하고 개별 업로드 이력 상세로 연결한다. 업로드 계정만 해당 미완료 파일을 조회하며, 다른 계정에는 해당 파일의 정보와 링크를 표시하지 않는다. 이력을 삭제하면 사용자 목록과 상세에서 숨기되 원래 업로드 총수, 정상 파일과 유형 그룹은 유지한다. 내부 기록과 기존 원본 보관 기간은 변경하지 않는다.

### 미확정 사항

| 항목 | 미확정 내용 |
| --- | --- |
| 제외 파일 | 원본 보관 및 삭제 시점, 검토 시작 전 제외 취소 제공 여부 |
| 추출 중 취소 파일 | 묶음 이력 표시와 재진입 방식 |
| 그룹 저장 실패 | 중복 저장 방지 재시도 및 부분 저장 복구 방식 |

자동 재시도 동작은 확정된 기준 없이 적용하지 않는다.
