## 핵심 규칙 요약표

| 구분 | 핵심 적용 기준 |
| --- | --- |
| 유형 판별 | `시험성적서/TEST REPORT`·시료명·채취일자·시험기간에 연결된 `시험결과` 영역에서 판정요원별 희석배수 상세표와 `Sample No. / Dilution multiple / 판정결과` 최종 요약표를 모두 확인. 페이지·표 위치·요원 수·배수 값은 가변. 필수 구조 미확인 시 확정하지 않음 |
| 보고서 구분 | 채취일자·시험기간·시료명 중 비교 가능한 값의 변경 또는 성적서번호 차이로 구분. 반복 기본 정보만으로 새 보고서를 만들지 않음. 같은 보고서의 페이지 연속·미완결 표 대응이 확인될 때만 연결하고 소속 불명 구간은 별도 보존 |
| 추출 범위 | 제목·기본 정보에서 시작하여 다음 별도 보고서 직전 또는 파일 끝까지 소속을 확인. 결과는 연결된 최종 요약표 데이터 행만 생성. 개별 판정요원 감지값·허용기준·판정결과·주석은 최종 수치로 사용하지 않음 |
| 시료·날짜·기관 | 기본 정보 시료명·채취일자, 시험기간 시작일, 하단 발행기관명 추출. 기간은 종료일 - 시작일 + 1, 명시적 단일 날짜는 1일. 날짜만 있으면 시각 NULL, 시료명 속 시각은 전용하지 않음 |
| 물질·분석법·결과 | 상세표 `시험방법` 셀의 분석 대상명·시험항목 코드·시험방법명을 읽고 요약표 시료와 연결. 분석법 표시값은 코드 + 방법명, 고시번호는 별도 필드. 결과는 `Dilution multiple` 셀만 사용하며 단위는 추정하지 않음 |
| 값·정밀도 | 0은 유효 수치. 빈 결과·비수치도 시료 소속이 확정된 행은 유지하며 수치 NULL과 원문·검증 정보 반환. Decimal과 원문 자릿수를 보존하고 개별 감지값으로 재계산하지 않음 |
| 지역 매칭 | 시료명·지역 입력값 → [지역 매칭](<../../matching-rules/location.md>) → 해당 지점·DB 좌표. 미매칭 또는 서로 다른 지점 후보가 겹치면 NULL. 직접 추출값과 DB 보완값을 구분 |
| 분석법 매칭 | 분석물질 추출·입력값을 [분석법 매칭](<../../matching-rules/analysis-method.md>)에 연결. 매칭 없음으로 직접 추출한 분석법을 지우지 않고 미연결 ID만 NULL. 직접 추출값과 매칭값을 출처별로 보존하며, 서로 다를 때의 적용 우선순위는 확인 필요 |
| 인터페이스 입력 | 추출·계산·매칭 후 비는 구분·매체·담당자·위치·BASE·채취법·단위 및 해석 불가 필드를 보완. 시험자·기술책임자를 담당자로 대체하지 않음 |
| 행 전개·출처 | 보고서별 기본 기록 + 최종 요약표 결과 N건을 반환하고 저장 시 결과별 독립 1:1 쌍으로 전개. 시험방법 전체·보고서 식별값·결과 위치를 보존하고 EXTRACTED·SYSTEM·MATCHED를 구분 |

## 파일 읽기 및 유형 판별

### 파일 읽기

| 항목 | 처리 기준 |
| --- | --- |
| 확장자·파일 형식 | `.pdf`. 확장자의 대소문자 구분 없음. PDF 파서로 실제 문서 구조를 읽을 수 있어야 함 |
| 추출 방식 | Python의 pdfplumber 등으로 페이지별 텍스트·단어 좌표·선·표·셀 위치를 추출. 단순 전체 문자열의 줄 순서만으로 필드를 연결하지 않음 |
| 페이지 기준 | 파일의 첫 페이지를 물리적 1페이지로 계산. 문서에 인쇄된 페이지 번호는 별도 보존 |
| 읽기 순서 | 물리적 페이지 순서, 페이지 내부의 보고서 영역 순서로 처리. 한 페이지 안의 복수 보고서와 여러 페이지에 걸친 보고서를 모두 구분 |
| 좌표 기준 | 회전·페이지 크기를 반영한 페이지 좌표 사용. 왼쪽 위 기준의 `x0, top, x1, bottom`과 페이지 크기·좌표 단위 보존 |
| 텍스트 중복 | 동일 위치에 겹친 동일 문자·동일 셀을 중복 인식한 경우만 하나로 처리하고 원본 위치 보존. 서로 다른 위치의 동일 값은 삭제하지 않음 |
| 텍스트를 읽을 수 없는 영역 | 필수 제목·라벨·결과가 이미지이거나 글자가 깨져 구조를 확인할 수 없으면 OCR 또는 수동 확인 필요로 반환. 빈 문자열을 정상 추출로 처리하지 않음 |
| 이미지 정보 | 로고·직인·수기 서명을 업무값으로 추정하지 않음. 인쇄된 텍스트를 우선 사용 |

### 라벨·표 구조 해석

| 대상 | 처리 기준 |
| --- | --- |
| 한글 라벨 | 판별용 라벨에서 공백·탭·줄바꿈을 제거하여 비교. `시 료 명`과 `시료명`, `시 험 결 과`와 `시험결과`를 동일하게 인식 |
| 영문 라벨 | 공백·줄바꿈을 정리하고 대소문자를 구분하지 않아 비교. 마침표가 있는 `Sample No.`와 마침표가 없는 `Sample No` 허용 |
| 최대·최소 제목 | `최대·최소 제외`, `최대 최소 제외`, `최대/최소 제외`를 허용. 다른 의미의 제목으로 임의 치환하지 않음 |
| 라벨과 값 | 라벨이 속한 셀 또는 같은 정보 영역의 오른쪽 값 영역을 연결. 다음 라벨·다른 열·표 경계를 넘지 않음. 값이 여러 줄이면 동일 값 영역 내부만 결합 |
| 표 제목 | 다단·병합 헤더를 해석하여 열 의미를 결정. 판정요원 수·희석배수 값·하위 열 수와 관계없이 제목으로 열을 찾음 |
| 표 탐지 실패 | 선 기반 탐지가 실패하면 제목 위치와 단어 정렬로 행·열을 복원. 제목과 결과 셀의 대응이 유일하지 않으면 확인 필요로 반환 |
| 외곽선 오인 | 페이지 장식·테두리로 만든 표 후보 중 열 제목과 독립된 결과 행을 식별할 수 없는 후보는 제외. 같은 셀 좌표를 포함한 중복 후보는 한 번만 처리 |
| 원문 보존 | 위 정규화는 판별·비교용 사본에 적용. 최초 추출 문자열과 위치는 수정하지 않음 |

### 날짜·기간 해석

| 항목 | 처리 기준 |

| 허용 날짜 | 연·월·일이 명시된 `YYYY. MM. DD`, `YYYY/MM/DD`, `YYYY-MM-DD`, `YYYY년 M월 D일`. 월·일 1자리와 마지막 마침표 허용. 달력상 유효성 검증 |

## 원본 위치 및 추출 상태

| 항목 | 기록 기준 |
| --- | --- |
| 기본 기록 `source_locator` | 실제 물리적 페이지와 보고서 영역 좌표의 목록. 여러 페이지에 걸치면 모든 관련 구간 보존 |
| 결과 `source_locator` | 결과 셀, 요약표 시료 셀, 연결된 시험방법 셀의 물리적 페이지·좌표. 서로 다른 페이지이면 각각 기록 |
| 위치 표현 | `page={p}; bbox=({x0},{top},{x1},{bottom})` 형태. 페이지·좌표는 파서가 계산한 값 사용 |
| `source_snapshot` | 컬럼별 최초 문자열·해석값·원본 위치 보존. 성적서번호·시험기간 전체·종료일·시험방법 전체는 구분·계산 근거인 보조 원본 항목으로 함께 보존 |
| 직접 추출 필드 | 유의미한 원문을 확보하면 `was_extracted=true`, `value_source=EXTRACTED`. 변환 실패 시 원문·오류와 NULL 업무값을 함께 보존 |
| 미추출 필드 | 빈 셀·없는 영역은 `was_extracted=false`. 형식 오류가 난 추출값과 구별 |
| 계산·시스템 필드 | 순서·날짜 정밀도·분석 기간은 `was_extracted=false`, `value_source=SYSTEM` |
| 최초 상태 | `is_modified=false`. 검증 문제가 없으면 `validation_issues=[]` |
| 반복 출처 | 같은 보고서의 반복 라벨에서 동일 값을 확인하면 업무값은 한 번 저장하고 확인한 위치들을 보존. 충돌하면 마지막 값으로 덮어쓰지 않음 |

### 파서 반환과 저장 행 변환

| 대상 | 변환 기준 |
| --- | --- |
| 파서 반환 구조 | 원본 기록별 `records[].basic`과 `records[].results[]`의 1:N 구조 유지. 이하 추출·구분 예시의 `record_order`는 파서의 원본 기록 순서 |
| 원본 기록 순서 | 파서 `record_order`를 DB 기본 기록의 `source_record_order`로 매핑. 같은 원본에서 파생된 모든 행에 같은 값 보존 |
| DB 행 순서 | 공통 저장 계층이 파서의 원본 기록 순서 → 그 안의 `result_order` 순서로 전체 결과를 펼쳐 DB `record_order`를 1부터 연속 부여 |
| 결과 순서 | DB `result_order`는 파서의 원본 기록 내 결과 순서를 그대로 보존. 결과별 기본 기록을 생성해도 1로 재설정하지 않음 |
| 저장 쌍 | 펼쳐진 결과마다 해당 `basic`을 복사한 독립 기본 기록 1건과 결과 1건을 1:1로 생성. 서로 다른 결과가 기본 기록을 공유하지 않음 |
| ID 발급 | 공통 저장 계층이 최초 검토 행 생성 시 각 쌍의 `record_id`·`result_id`를 발급하고 연결. 최종 저장에서는 같은 ID 재사용 |
| 보존 | 원본 위치·스냅샷은 해당 쌍에 연결하여 보존. 최초 ID와 `record_order`·`source_record_order`·`result_order`는 검토·최종 저장 및 화면 정렬 중 변경하지 않음 |
| 파서 책임 | 원본 추출과 검증 정보 반환만 수행. DB 조회·저장, 마스터 ID 발급은 수행하지 않음 |
