## 보고서 구분 및 추출 구간

### 시작·연속·종료 판정

| 상황 | 판정 및 처리 |
| --- | --- |
| 시작 | 기본 정보의 `시험결과` 아래에서 물질명·단위 헤더와 시료 행렬을 찾음. 빈 `시험대상품목/물질/시료명` 필드를 시료명으로 사용하지 않음 |
| 보고서 식별 | 제목에 연결된 보고서번호·발행번호·시험기간을 각 라벨별로 보존. 페이지에 반복되는 같은 식별값은 기존 보고서로 연결 |
| 새 보고서 | 다른 보고서번호·시험기간과 새 기본 정보가 나타나면 별도 보고서로 구분. 누락된 값을 같다고 간주하지 않음 |
| 물질 블록 변경 | 새 물질명·단위 헤더가 나타나면 그 이후 행에 새 열 구성을 적용. 같은 시료가 반복되면 그 시료의 다른 물질 결과로 연결 |
| 헤더 없는 다음 페이지 | 같은 보고서, 직전 미종료 블록과 일치하는 열 개수·정렬, 이어지는 시료 행이 확인되면 직전 물질명·단위를 상속. 새 헤더 또는 보고서가 시작되면 상속 중단 |
| 연속 근거 부족 | 직전 블록의 물질 열과 다음 페이지 값의 대응이 유일하지 않으면 결과 원문·위치를 보존하고 확인 필요. 숫자 개수만으로 상속하지 않음 |
| 표 하단 가로선 | 해당 블록의 경계로 사용하되 보고서 종료로 단정하지 않음. 뒤에 새 물질 헤더·연속 시료 행이 있는지 확인 |
| 종료 | 결과표 이후 안내문·확인·작성자/승인자·발행일·직인 등 마감 영역으로 전환되고 연속 결과 영역이 없으면 종료 |
| 제외 | 반복 머리글·주소·연락처·양식번호·서명·발행일·직인은 결과에서 제외. 인쇄 총 페이지 수는 추출 종료 기준으로 사용하지 않음 |

| 보고서 공통값 | 유효한 날짜·시험기간 등 공통 필드만 같은 보고서의 각 시료에 적용. 서로 다른 보고서에는 전파하지 않음 |

### 지역·관측 지점 및 좌표 매칭

시료명 앞부분의 정식 지점명 또는 승인된 지역 별칭으로 후보를 찾는다. 별칭 뒤 공백·숫자·구분기호 경계를 확인하여 다른 지명의 일부를 잘못 연결하지 않으며, 시료명 전체의 포함 검색으로 확대하지 않는다. 같은 지점을 가리키는 별칭은 하나의 후보로 보고 서로 다른 지점이 겹치면 확인 대상으로 둔다.

| 항목 | 처리 기준 |
| --- | --- |
| 매칭 대상 | 각 시료의 지역 표현을 최신 지역 DB의 정식 관측 지점 또는 승인된 별칭에 연결. 시료명 원문은 변경하지 않음 |
| 별칭 | 승인된 청림→포항 청림, 해도→포항 해도, 태인→광양 태인, 묘도·온동→여수 묘도(온동) 등의 연결 사용. 새로운 단축명·오타를 추측해 추가하지 않음 |
| 지점 선택 | 후보가 한 지점으로 유일할 때만 확정. 후보 없음·서로 다른 여러 지점·지역 표현 불명확 시 위치값 NULL과 사용자 확인 대상으로 반환 |
| 연결값 | `location_name`, `latitude`, `longitude`를 같은 DB 행에서 함께 확보. 실제 마스터 연결 근거가 있을 때만 `location_id` 설정 |
| 좌표 출처 | PDF 직접 추출이 아닌 MATCHED. 지역 표현·연결 지점·DB 원본 좌표를 최초 스냅샷에 보존 |
| 정밀도 | DB의 십진수 좌표를 사용. 저장 시 통합 스키마의 `DECIMAL(13,10)`과 십진수 반올림 기준 적용. 원본 좌표는 별도 보존하고 중복 반올림하지 않음 |
| 적용 범위 | 같은 시료의 모든 물질 결과에 그 시료의 지점·좌표를 적용. 파일의 첫 지점을 다른 시료에 일괄 적용하지 않음 |

## 물질별 결과 추출

### 행렬을 물질별 결과로 변환

| 항목 | 처리 기준 |
| --- | --- |
| 물질명 | 현재 블록의 첫 헤더 행에서 열별 물질명 추출. Al·Ca 같은 원문 표기를 임의로 한글명이나 다른 물질로 교체하지 않음 |
| 단위 | 물질 헤더 바로 아래 같은 열의 단위 사용. 같은 블록에도 mg·ug가 함께 있을 수 있으므로 첫 단위를 전체 열에 적용하지 않음 |
| 단위 표기 연결 | 이 유형의 원문 `ug`는 `source_snapshot`에 보존하고 업무값 `unit`·DB·화면은 `μg`로 표준화. 수치는 변환하지 않으며 `mg`는 그대로 유지. 유효한 단위 목록 연결이 확인될 때만 `unit_option_id` 부여 |
| 결과 셀 | 시료 행과 물질 열이 교차하는 값 하나를 결과 1건으로 생성. 시료명 끝의 숫자·PM10·양식번호 등을 결과에 포함하지 않음 |
| 열·행 경계 | 헤더 중심·주변 열 간격·글자 좌표로 경계 계산. 숫자가 시료명에 붙어 보이더라도 전체 줄의 공백 개수로 분리하지 않음 |
| 누락 셀 | 중간 값이 비어 있으면 그 물질 결과를 NULL로 유지하고 뒤 열을 당기지 않음. 행·열 대응이 불명확하면 해당 영역 확인 필요 |
| 페이지 상속 | 헤더 없는 연속 행은 확인된 직전 블록의 물질·단위에 연결. 원본 위치에 상속한 헤더의 페이지·범위도 함께 보존 |
| 시료별 결과 연결 | 같은 시료의 다른 물질 블록을 하나의 `results[]`에 이어 붙임. 물질 순서는 문서상 블록 순서와 블록 안의 왼쪽→오른쪽 순서 |
| 반복·중복 | 같은 물질·시료의 별도 원본 셀을 자동 삭제·평균하지 않음. 동일 좌표의 중복 탐지만 제거하고 실제 반복값은 보존·확인 |

### 물질별 추출 예시 및 컬럼 매핑

| 항목 | 매핑 컬럼 | 샘플 원본 위치·값 | 실제 추출·변환 예시 | 추출·변환 규칙 |
| --- | --- | --- | --- | --- |
| 결과 순서 | `result_order` | 첫 시료의 Al 열, 뒤 블록의 V 열 | Al: `1`, V: `6` | SYSTEM. 같은 시료의 물질 블록을 연결 |
| 분석물질 | `substance_name` | 1페이지 헤더 `Al` | `Al` | EXTRACTED. 해당 열에만 적용 |
| 단위 | `unit` | Al 아래 `mg`, Mn 아래 `ug` | Al: `mg`, Mn: `μg` | 열별 단위 적용, 원문·매칭값 구분 |
| 결과 원문·표시값 | `result_raw`, `result_text` | 청림 PM10 #4-3 · Al `1.50` | `1.50`, `1.50` | EXTRACTED. 소수 자릿수 보존 |
| 숫자 결과 | `result_value` | 같은 결과 셀 `1.50` | 정밀 소수 `1.50` | 전체 문자열이 유효한 숫자일 때 Decimal 변환 |
| 실제 0 | `result_raw`, `result_text`, `result_value` | 해도 PM10 #4-1 · Be `0.00` | 원문·표시 `0.00`, 수치 `0.00` | 0은 유효한 수치이며 NULL로 바꾸지 않음 |
| 헤더 상속 | `substance_name`, `unit` | 3페이지 첫 행 해도 PM10 #4-2 · 첫 값 `0.00` | Ni, `μg`, 결과 `0.00` | 2페이지 마지막 블록 헤더·단위에 연결 |

### 숫자·비수치 해석

| 구분 | 처리 기준 |
| --- | --- |
| 숫자 | 앞뒤 공백 제거 후 부호·소수·지수 표기를 포함한 전체 문자열 검증. Decimal 사용, 임의 반올림·수치 환산 금지 |
| 원문 정밀도 | `1.50`, `13.0`, `0.00` 등 원문과 표시 자릿수 보존. JSON 전달 시 정밀 소수를 문자열로 표현 |
| 비수치 | `n.d`, `ND`, 부등호 등은 원문·표시값을 보존하고 수치만 NULL. 0이나 검출한계로 대체하지 않음 |
| 누락 | 실제 빈 셀과 비수치 표기를 구분. 식별한 빈 셀의 원문은 빈 문자열, 업무값은 NULL. 셀을 식별하지 못하면 원문도 NULL 및 확인 정보 기록 |

샘플 전수 대조: 360개 값 모두 수치이며 실제 0은 32개다. 단위 원문은 mg 96개·ug 264개다.

## 원본 보존·오류 처리

| 항목 | 처리 기준 |
| --- | --- |
| 원본 위치 | 보고서·시료 행·물질 헤더·단위 헤더·결과 셀 각각의 물리적 페이지와 bbox 보존. `page={p}; bbox=({x0},{top},{x1},{bottom})` |
| 원본 스냅샷 | 시료명·날짜 라벨과 문자열·기간·결과 원문·단위 원문 및 보고서번호 보존. 상속한 헤더 위치와 목록 매칭 출처는 결과 셀 위치와 구분 |
| 직접 추출 | PDF에서 읽은 시료·물질·결과·날짜는 `was_extracted=true`, `value_source=EXTRACTED`. 위치 좌표는 직접 추출값으로 표시하지 않음 |
| 단위 정규화 | `unit`은 `was_extracted=true`, `value_source=EXTRACTED`. 최초 원문 `ug`와 정규화 해석값 `μg`를 스냅샷에 구분해 보존. 실제 단위 목록 ID 연결 시 `match_status=MATCHED`, 미연결 시 ID는 NULL |
| 매칭·계산 | 지역·좌표와 목록에서 보완한 값은 MATCHED, 순서·기간·정밀도는 SYSTEM. 최초 `is_modified=false`, 검증 사항이 없으면 `validation_issues=[]` |
| 경계·셀 오류 | 보고서 연결·헤더 상속·동명 시료 대응·열 정렬이 불명확한 범위만 확인 대상으로 분리. 확인된 값을 버리거나 인접 값을 임의 전파하지 않음 |
| 파일 오류 | 암호화·파싱 실패·필수 유형 구조 미확인은 정상 추출 완료로 처리하지 않음 |

## 공통 처리 연결

| 대상 | 처리 기준 |
| --- | --- |
| 파서 반환 | 시료별 `records[].basic` + `records[].results[]` 1:N. 샘플은 기본 기록 24건, 각 결과 15건 |
| 순서 | 원본 보고서 순서→시료 최초 출현 순서로 파서 `record_order`, 각 시료의 물질 블록→열 순서로 `result_order` 부여 |
| 매칭 계층 | 시료별 지역·목록 연결은 공통 계층에서 수행. 파서는 원문·시료 관계·후보 근거를 반환하고 DB 조회·ID 발급을 수행하지 않음 |
| 저장 변환 | 결과마다 basic을 복사한 독립 `review_record`·`review_result` 1:1 쌍 생성. 샘플은 360쌍 |
| 원본·DB 순서 | 파서 `record_order`를 `source_record_order`에 보존. 기본 기록 순서와 그 결과 순서로 펼쳐 DB `record_order`를 부여 |
| 최종 저장 | 검토·유형별 검증 후 `analysis_record`·`analysis_result`에 반영. 최초 ID·순서·원본 스냅샷 유지 |
