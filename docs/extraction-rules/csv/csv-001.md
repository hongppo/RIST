## 파일 읽기 및 유형 판별

| 항목 | 처리 기준 |
| --- | --- |
| 확장자 | `.csv`. 확장자의 대소문자 구분 없음 |
| 문자 인코딩 | UTF-8, BOM 유무 모두 허용. 해석 실패 시 오류 반환; 깨진 문자를 대체하여 처리하지 않음 |
| CSV 형식 | 쉼표 구분, 큰따옴표로 감싼 셀과 이스케이프된 큰따옴표를 처리하는 CSV 파서 사용 |
| 행·열 번호 | 첫 CSV 행을 1행, 첫 셀을 A열로 계산. 빈 행을 제거하거나 헤더를 제외하기 전에 원본 행 번호 부여 |
| 짧은 행 | 존재하지 않는 열은 값 없음으로 처리. 시작 행처럼 A열만 존재하는 행 허용 |
| 유형 후보 | A열에 `RIST_Sample_inlet-`가 포함된 행이 2개 이상 존재 |
| 유형 확정 | 아래 추출 구간 조건을 충족하고, 행 제외 규칙 적용 후 물질별 결과가 1건 이상 존재 |
| 고정하지 않는 값 | 업로드 파일명, 시작·종료 행 번호, 물질 수, 분석일시, 단위 |

- 행 번호는 CSV 파서의 논리 행 기준. 따옴표 안 줄바꿈을 별도 행으로 세지 않음.
- 문자열 검색은 대소문자 구분. 판별용 셀은 앞뒤 공백을 제거하여 비교하고 원본 문자열은 별도 보존.

## 추출 구간

| 순서 | 대상 | 규칙 |
| --- | --- | --- |
| 1 | 시작 행 `S` | A열을 위에서부터 읽어 `RIST_Sample_inlet-`를 포함하는 **두 번째 행** 선택 |
| 2 | 공통 정보 | `A{S}`에서 시료명·분석일시·단위 추출 |
| 3 | 종료 행 `E` | `S` 다음 행부터 C열을 읽어 값이 `# Measurements`와 완전히 일치하는 **첫 행** 선택 |
| 4 | 결과 후보 구간 | `S+1`부터 `E-1`까지의 C·D열 |
| 5 | 결과 행 확정 | 결과 후보 구간에 물질별 행 제외·변환 규칙 적용 |

- `S` 이전의 `# Measurements`는 무시. `S`와 `E` 행 자체는 결과에서 제외.
- `E` 이후 구간은 추출하지 않음. `by reagent`, `by product` 구간을 합산하거나 추가하지 않음.
- `E`를 찾기 전에 A열에서 다음 `RIST_Sample_inlet-` 헤더가 나타나거나 파일이 끝나면 구간 오류. 뒤쪽 구간의 종료 표시로 대체하지 않음.

## 공통 항목 추출

### 시작 행 해석

```text
{시료명}_inlet-{중간 식별번호}-{YYYYMMDD}-{HHmmss}.xml: {구간명} ({단위})
```

| 대상 | 해석 규칙 |
| --- | --- |
| 시료명 | `_inlet-` 앞의 문자열. 앞뒤 공백만 제거 |
| 분석 날짜·시간 | `.xml` 직전의 날짜·시간 토큰을 각각 추출·검증. 정상 형식은 `-([0-9]{8})-([0-9]{6})\.xml`이며 날짜는 YYYYMMDD, 시간은 HHmmss로 해석 |
| 단위 | 시작 행 문자열의 **마지막 괄호** 안 문자열. 앞뒤 공백 제거 후 모든 결과 행에 동일하게 적용 |
| 중간 식별번호 | 업무 컬럼으로 추출하지 않음. 시작 행 원문에는 보존 |

### 공통 항목 추출 예시 및 컬럼 매핑

| 샘플 원본 위치 | 셀 전체 원문 |
| --- | --- |
| `A256` | `RIST_Sample_inlet-9923-20251105-174039.xml: Analyte concentration (ppb)` |

| 항목 | 매핑 컬럼 | 샘플 원본 위치 | 샘플 원본 값·해석 대상 | 실제 추출·계산 예시 | 추출·변환 규칙 |
| --- | --- | --- | --- | --- | --- |
| 원본 기록 순서 | 파서 `record_order` | 해당 없음 | 해당 없음 | `1` | SYSTEM. 원본 기본 기록 1건이므로 파서에서는 1 유지. DB source_record_order로 매핑 |
| 시료명 | `sample_name` | `A256` | 원문 중 `RIST_Sample` | `RIST_Sample` | EXTRACTED. 시작 행의 `_inlet-` 앞 문자열에서 앞뒤 공백 제거 |
| 분석 날짜 | `analyzed_date` | `A256` | 원문 중 `20251105` | `2025/11/05` | EXTRACTED. `.xml` 직전 날짜·시간 토큰 중 날짜를 검증하여 DATE로 변환 |
| 분석 일시 | `analyzed_at` | `A256` | 원문 중 `20251105-174039` | `2025/11/05 17:40:39` | EXTRACTED. 유효한 날짜·시간을 초 단위 TIMESTAMP로 변환. 시간대 부여하지 않음 |
| 분석 정밀도 | `analyzed_precision` | `A256` | 원문 중 `20251105-174039` | `SECOND` | SYSTEM. 날짜·시간이 모두 유효하고 초까지 존재하면 SECOND. 부분 오류 처리는 아래 기준 적용 |
| 분석 기간 | `analysis_duration_days` | `A256` | 원문 중 `20251105` | `1` | SYSTEM. 유효한 분석 시작 날짜가 있으면 공통 계산값 1. 시작 날짜가 없으면 NULL |

- 원문에 없는 시간대는 부여하지 않으며, 분석일시를 임의로 UTC로 변환하지 않음.
- 정상 형식에 일치하지 않아도 헤더 구조에서 날짜 토큰을 유일하게 식별할 수 있으면 별도 검증. 시간 누락·자리수 오류만으로 유효한 날짜를 버리지 않으며, 날짜 위치가 불명확하면 추정하지 않음.
- 날짜만 유효하고 시간이 잘못되면 `analyzed_date`만 보존, `analyzed_at=NULL`, `analyzed_precision=DATE`로 설정하고 시간 오류 기록.
- 날짜 해석 실패 시 `analyzed_date`·`analyzed_at`·`analysis_duration_days`는 NULL, `analyzed_precision=UNKNOWN`. 시작 행 원문과 오류 보존.
- 분석 기간 1일은 시작일만 있는 경우의 공통 계산값. 파일에서 기간을 직접 추출한 것으로 표시하지 않음.

## 미추출 항목 및 목록 연결

| 구분 | 항목 | 초기 처리 |
| --- | --- | --- |
| 기본 정보 | 구분, 매체, 담당자, 분석 기관 | 표시값·목록 ID 모두 NULL |
| 채취 일자 | `collected_date`, `collected_at`, `collected_precision` | 날짜·일시 NULL, 정밀도 `UNKNOWN` |
| 위치 | `location_id`, `location_name`, `latitude`, `longitude` | 모두 NULL |
| 물질별 방법 | BASE, 채취법, 분석법 | ID·명칭·코드 모두 NULL |
| 분석법 세부 필드 | `analysis_method_notice_number`, `analysis_method_test_code` | 추출 근거 없음. 모두 NULL |
| 추출값의 목록 연결 | `substance_id`, `unit_option_id` | 미매칭 시 NULL. 추출한 물질명·단위는 유지 |

- 파일명·폴더명·로그인 회원으로 담당자·기관·매체·위치를 추정하여 채우지 않음.
- 목록 매칭은 추출값을 보존한 상태에서 수행. 매칭되지 않은 값을 임의의 목록 ID에 연결하거나 목록 항목을 자동 생성하지 않음.
- SQL NULL 사용. 문자열 `NULL`, 안내 문구, 임의 예시값을 저장하지 않음.

## 원본 위치 및 추출 상태

| 항목 | 기록 기준 |
| --- | --- |
| 기본 기록 `source_locator` | `A{S}; C{첫 결과 행}:D{마지막 결과 행}`. 실제 계산한 행 번호 사용 |
| 결과 `source_locator` | 각 결과의 `C{행}:D{행}; A{S}`. 물질·결과 위치와 공통 단위의 출처 기록 |
| `source_snapshot` | 컬럼별 최초 셀 문자열·해석값·원본 위치 기록. 물질명 C열, 결과 D열, 공통 항목 A열 출처 보존 |
| 직접 추출 필드 | `field_meta.was_extracted=true`, `value_source=EXTRACTED`. 형식 오류가 있으면 원문과 오류도 보존 |
| 미추출 필드 | `field_meta.was_extracted=false`. 미입력 상태와 추출 후 해석 실패 상태를 구분 |
| 계산·시스템 필드 | `field_meta.was_extracted=false`, `value_source=SYSTEM`. 분석 기간·정밀도·순서 등에 적용 |
| 최초 상태 | `field_meta.is_modified=false`. 검증 문제가 없으면 `validation_issues=[]` |

- 추출 상태는 셀의 유의미한 값 유무로 구분. 빈 셀·없는 열을 추출 완료값으로 표시하지 않음.
- `field_meta`의 입력 방식·목록 연결 상태 등 공통 구조는 [통합 스키마](<../../rist-schema.md>) 적용.

## 오류 처리

| 구분 | 조건 | 처리 |
| --- | --- | --- |
| 파일 오류 | 인코딩 또는 CSV 파싱 실패 | 추출 중단. 원본을 보존하고 읽기 오류 반환 |

| 구간 오류 | 종료 표시 누락, 종료 전 다음 구간 헤더 등장 | 추출 중단. 뒤쪽 구간·파일 끝으로 대체하지 않음 |
| 결과 없음 | 행 제외 후 결과가 0건 | 추출 중단. 빈 기본 기록을 정상 추출로 반환하지 않음 |
| 공통 항목 오류 | 시료명·분석일시·단위 해석 실패 | 해당 값은 NULL 또는 유효한 부분만 보존. 기본 기록에 검증 항목 기록; 단위 오류는 각 결과에도 연결 |
| 결과 확인 필요 | 물질명은 있으나 결과 누락·비수치 | 해당 결과 행 보존. 원본 위치·원문·검증 항목 반환 |

- 구간을 확정할 수 있는 필드 오류는 다른 정상 결과의 추출을 막지 않음.
- `validation_issues`에 대상 컬럼·오류 코드·수준·안내를 기록. 비수치 표현의 최종 저장 허용 여부는 유형의 `input_schema`로 검증.

## 공통 처리 연결

| 구분 | 적용 기준 |
| --- | --- |
| 스크립트 반환 | 원본 기본 기록 1건의 `basic`과 전체 `results[]`, 원본 위치·추출 상태·검증 항목. 파서 `record_order=1` 유지 |
| 검토 데이터 | 공통 저장 계층이 아래 변환 기준에 따라 결과 행마다 독립적인 `review_record`·`review_result` 1:1 쌍을 생성 |
| 업로드 정보 | 파일명·업로더·파일 유형·적용 규칙 버전은 `uploaded_file`에서 관리 |
| 규칙 버전 | 작업 시작 시 결정된 버전으로 실행. 실행 중 최신 버전으로 교체하지 않음 |
| 최종 저장 | 검토 완료 후 공통 저장 처리에서 `analysis_record`·`analysis_result`로 반영 |

### 파서 반환과 저장 행 변환

| 대상 | 변환 기준 |
| --- | --- |
| 파서 반환 구조 | 원본 기록별 `records[].basic`과 `records[].results[]`의 1:N 구조 유지. 이하 추출·구분 예시의 `record_order`는 파서의 원본 기록 순서 |
| 원본 기록 순서 | 파서 `record_order`를 DB 기본 기록의 `source_record_order`로 매핑. 같은 원본에서 파생된 모든 행에 같은 값 보존 |
| DB 행 순서 | 공통 저장 계층이 파서의 원본 기록 순서 → 그 안의 `result_order` 순서로 전체 결과를 펼쳐 DB `record_order`를 1부터 연속 부여 |
| 결과 순서 | DB `result_order`는 파서의 원본 기록 내 결과 순서를 그대로 보존. 결과별 기본 기록을 생성해도 1로 재설정하지 않음 |
| 저장 쌍 | 펼쳐진 결과마다 해당 `basic`을 복사한 독립 기본 기록 1건과 결과 1건을 1:1로 생성. 서로 다른 결과가 기본 기록을 공유하지 않음 |
| ID 발급 | 공통 저장 계층이 최초 검토 행 생성 시 각 쌍의 `record_id`·`result_id`를 발급하고 연결. 최종 저장에서는 같은 ID 재사용 |
| 보존 | 원본 위치·스냅샷은 해당 쌍에 연결하여 보존. 최초 ID와 `record_order`·`source_record_order`·`result_order`는 검토·최종 저장 및 화면 정렬 중 변경하지 않음 |
| 파서 책임 | 원본 추출과 검증 정보 반환만 수행. DB 조회·저장, 마스터 ID 발급은 수행하지 않음 |

| 파서 원본 기록 순서 | 파서 결과 순서 | DB source_record_order | DB result_order | DB record_order | 저장 단위 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 1 | 1 | 독립 기본 기록·결과 1쌍 |
| 1 | 2 | 1 | 2 | 2 | 독립 기본 기록·결과 1쌍 |
| 2 | 1 | 2 | 1 | 3 | 독립 기본 기록·결과 1쌍 |
